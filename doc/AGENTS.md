# 项目文档维护规则

## 文档职责

- `TODO.md` 是当前待办的唯一入口，记录明确动作、完成状态和阻塞项。
- `Roadmap.md` 记录阶段目标与验收条件，不复制细粒度待办。
- `PRD/` 记录目标、使用场景、范围、约束和验收标准。
- `decisions/` 记录重要决策的背景、候选方案、结论、依据与影响。
- `note/` 按主题积累可复用知识、排查结论和验证方法，不保存逐轮聊天流水账。
- `archive/` 保存被替代的历史材料，默认不读取。

## 更新与证据

1. 先检索现有主题再新增文件，优先更新同一主题，避免多个互相矛盾的状态来源。
2. 事实、计划、假设与待确认事项明确区分；检查结论附日期、检查范围及必要命令或来源。
3. 待办完成必须有可核验结果。未执行、未通过或依赖用户输入的事项保留未完成状态并注明原因。
4. 新增重要文档后更新相关索引。新增模块时视需要在对应目录建立局部 `AGENTS.md`。
5. 归档文件应注明被什么替代，并更新有效文档的引用；涉及删除或搬移已有材料时遵循用户授权范围。
6. `README.md` 只描述对外可用的信息，内部状态由根目录 `AGENTS.md` 和上述文档承载。
7. 不使用 `LAST_RUN.md`；未经明确版本更新请求不创建或修改 `CHANGELOG.md`。

## 命名

主题文件使用简短的英语名称，例如 `data-validation.md`。决策文件使用递增编号，例如 `0001-project-memory.md`。日期只在具有时间属性的报告中使用，避免为同一长期主题反复创建日期副本。
